# MiniVectorDB engineering

定位项目：当前工作区的 `minivectordb/`，或含 `docs/CONTRACT.md` 的当前仓库。以下路径均相对项目根。

接手先读 `HANDOFF.md`、`optimization/state.json`、`AGENTS.md`，再按改动读 `docs/CONTRACT.md` 和 `docs/ARCHITECTURE.md`。检查 git 工作树、基线 tag、源码指纹和实际测试报告；历史通过不证明当前版本通过。

本项目使用 C++20、自研磁盘日志/主键映射/查询执行。通用 JSON/数学库允许；不要把执行交给 SQLite、RocksDB、Faiss、HNSWlib 等引擎。读协议用 `STDIO_PROTOCOL.md`；旧题意的纯 SQL 输入描述已被实际 JSONL 驱动替代。

开发时保持这些不变量：

- 每条失败语句不能留下局部修改；显式事务之前成功的语句仍在。先验证并暂存整条语句，再合入事务。
- COMMIT 成功响应前持久化；未响应提交允许整体保留或整体丢弃，不能部分生效。重建完成后才能 ready。
- exact 永远精确；先过滤再 TopK；float32 存储后计算欧氏距离；并列主键升序。
- `/data` 包含全部数据、日志、索引与临时文件；内存不能随全表大小无限增长。
- 派生向量索引不能暴露删除、旧版本或已回滚的数据。缓存和索引优化须解释事务覆盖层的可见性。

每轮从 `optimization/queue.md` 选择一个可证伪假设，建立独立实验目录，写明预期、变化、最低必要检查和停止条件；模板在 `optimization/experiment-template.json`。以真实 profile/资源数据定位原因，不只猜测热点。一次只改变能解释结果的一类因素。

先做针对性反例/差分验证，再做规模较小的筛选；通过后才进行三轮完整本地性能比较。按 `docs/VALIDATION.md` 选择检查：日志/提交/恢复变化必须带崩溃与重复恢复；内存结构变化带超内存数据；查询变化带独立精确 oracle 和过滤反例。通用文档修改无需重跑数据库。

保留失败假设、原始报告和样本条件。只有正确性通过且收益可重复，才采用候选；噪声或资源代价不明标记 inconclusive。不得修改公开断言、偷偷放宽容差、只挑某轮最好值、忽略失败点或把 ann 结果冒充 exact。相同二进制不因解释改写而重复全量测试。

默认一批最多三个候选或 45 分钟，随后检查收益、预算与剩余赛期再决定下一批；用户后续明确预算优先。不要自行运行无限优化循环。需要独立长线执行时按用户当次授权。
为记录和清理预留预算；总耗时包含归档，超时如实记录，不只报告性能执行时间。

输出：代码/构建身份、假设、差分、验证范围、原始报告路径、三轮结果或未比较理由、采用/拒绝/不确定，以及下一步。同步 `optimization/state.json`。提交平台和远端推送仅在用户授权时执行；本 skill 不新增授权。
