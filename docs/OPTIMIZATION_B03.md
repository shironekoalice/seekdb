# 第三批：profile 与 PK 等值定位

本批只评估一个引擎候选P02，45分钟上限，预留5分钟收尾。
先profile当前最佳P07，再实现和验证PK定位。点操作收益可重复，
默认性能负载的综合收益尚不稳定，因此未替换P07。
没有推送、正式提测或后台优化循环。时间与身份见
`evidence/optimization-b03/record-final.json`、`closure.json`。

## Profile 与改动

接手核对源码、tag、原生二进制和镜像，均匹配B02。
P07源码指纹为 `81b6fc0dec77f560b06a2cabefae9c84f427184467f0f8442e5cd77bd7e7f309`。
没有因接手重跑同一P07的全部验证。

独立RelWithDebInfo/-pg构建先跑10000行×128维、1000次向量查询，
再跑10000行点操作。profile包含装载、建索引和关闭，不能当平台T/B/M。
向量负载有10010000次load、10000000次matches和164891次File::read。
样本总量约2.28秒，distance self样本19.30%，JSON销毁10.96%；
内联、插桩和0.01秒采样限制归因精度，不据此承诺可实现收益。

SQL与独立预期值提前生成；B/M包含全轮装载、索引、预热、CRUD、关闭和sync。

默认查询没有PK等值谓词，P02不减少其行访问量。两组E方向不同，时间、顺序、
种子和宿主状态仍是混杂因素，未确立波动根因。不把第二组当稳定综合提升，
也不把第一组称作永久回归。
决定 `point_gain_verified_not_promoted_default_E_inconclusive`：
保存候选，当前最佳仍P07。
