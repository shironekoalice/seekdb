# 真实学习材料

当前评审只读 `agent/conversation.json`。本地源码、独立日志和本 Markdown 不会自动
成为学习证据；关键学生原话与真实结果需内嵌在 JSON 字符串。结构校验是
`python3 tools/evidence.py agent/conversation.json`。

当前可核对的学生贡献主要是：要求规划加赛、选择先强模型准备再切换模型长线优化、
要求准备基线/验证工具/三个 skill 并在同一会话交接。这些是实际的组织决策，
不能扩写成学生已理解 WAL、索引、事务或性能公式。工程实现和测试归 Agent/工具。
材料中的 `student_learning_evidence_incomplete:true` 是明确的缺口记录。

后续用户愿意参与时，可围绕真实问题自然形成学习链，例如：

- 在 marker 前后杀进程分别预期看到什么；为何未收到成功响应仍可能完整提交？
- 过滤条件只命中少量数据时，全表 TopK 后再过滤为什么有反例？
- 增大缓存是否一定提升综合 E；页缓存与 RSS 的区别如何影响测量解释？
- 对日志 checkpoint 方案，预测恢复时间收益和提交/索引一致性代价，然后用实测判断。

这些是可讨论问题，尚未发生的回答和实验不能记为完成。不要替用户写“我的理解”
或要求照读标准答案。长期无人参与的自动优化仍可保留真实工程结果，但不能伪造学习。

每个问题/修正链一个 unit，标 student/agent/tool 来源。重复测试不是新的学习贡献。
可选 `evidence_links` 指向 JSON 内字符串，以 RFC6901 pointer 和 ≤240 字符原文片段引用；
同一证据不跨 unit 重复加分。真正的计分由官方冻结的三轮评审完成，当前未提供该评审器。

公开规则的五维为问题理解与自主拆解、技术理解与迁移、独立验证与质疑、
实验与反馈迭代、取舍与反思。每个独立实例按0.5/1/1.5/2最高适用档，不按篇幅计分，
维度和原始分无固定上限；三轮各维取中位数相加后排名，排名再换算最多40分。
不能将“共80分”理解成材料里填满五个标题即可得分。
