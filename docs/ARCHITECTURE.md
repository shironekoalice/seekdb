# 当前基线的结构与代价

单进程、单客户端、最多一个显式事务。`src/sql.cpp` 负责词法/语法、类型校验、
float32 和 Unicode 语义；`src/storage.cpp` 负责执行、磁盘文件、提交与恢复；
`src/main.cpp` 只处理 JSONL 协议和错误边界。

## 文件与权威关系

`journal.mvdb` 是权威数据：16 字节头（magic、payload 长度、类型、校验）
加 CBOR 逻辑操作。操作为 schema/put/delete；空 commit frame 封闭一个事务。
记录引用为日志偏移+1，0 为删除标记。当前版本为 Linux x86_64 小端布局，
尚无升级迁移协议；不要把它描述为成熟通用存储格式。

`<table>.pk` 是可重建磁盘哈希链表，8192 个桶，每节点 24 字节
（key、最新引用、next）。P07缓存固定64 KiB桶头/活动映射，
另有全进程固定640 KiB节点缓存；容量不随行数增长，链节点仍存于磁盘。
节点缓存以映射身份和文件位置区分，写后更新，淘汰/未命中回读磁盘；
重建映射分配新身份。目录总内存随映射数量增长，节点缓存总量固定。
`<table>.flat` 是可重建向量文件（key、row_ref、float32 向量）；
只有 row_ref 等于当前主键映射时才可见。更新后的旧索引项不会命中。
现阶段扫描 flat 后仍加载行来执行过滤/距离，保留了明显的优化空间。

`transaction.tmp`、`<table>.pending` 是未提交覆盖层；`statement.tmp`、
`statement.pk` 用于一条语句验证和重复检测。它们都位于 `/data`，
启动时不作为已提交权威。LOCK 文件防止并发打开同一目录。

## 语句与事务

每条修改先生成完整 statement 文件；任何类型/主键/语义错误都发生在
合入 transaction 之前，因此不污染此前成功的事务语句。
查询合并 committed PK 和 pending 覆盖层，删除/更新以 pending 为准。
索引查询在显式事务中退回合并行视图，确保读到自己的修改。

提交把事务操作复制到日志，追加 commit frame，再 `fdatasync`，随后更新派生索引，
最后发成功响应。内部 I/O 错误终止进程，由重启恢复，避免继续暴露半套内存状态。
普通 SQL 错误则只失败当前语句，保留连接和此前事务操作。

恢复扫描完整且校验正确的 frame，只应用带 commit marker 的事务；尾部未完成操作被截去。
从日志重建所有主键/向量索引后才 ready。恢复中再次被杀，下一次仍从日志重建。
数据库进程退出但未回复的提交可能已经完整持久化；不能期待所有未回复提交都消失。

## 内存与查询

默认解码行 LRU 预算 32 MiB，可用 `MVDB_CACHE_BYTES` 调整（上限 512 MiB）。
缓存估算包含行、字符串和向量，不等于总 RSS；SQL 请求、JSON、TopK/结果、schema、
OS 页缓存另占空间。堆保存 TopK 投影和排序键，字符串按验证过的 UTF-8 码点序比较，
向量按 float32 存储后用 double 累计距离。

## 已知性能风险

- 恢复重放全部历史，无 checkpoint/日志回收；长期更新会增加恢复时间和磁盘占用。
- 磁盘 PK 查找在缓存未命中时含随机 pread，普通条件更新/删除和 SELECT 仍扫描，
  缺少 PK 定位快速路径。
- 每行重复解析谓词字面量/列解析，行拷贝、缓存维护和序列化可能占查询开销。
- flat 文件仍做 row load，旧版本堆积，没有真正 ANN 剪枝或 SIMD 专用路径。
- 固定哈希桶数量在大表下链长增长。缓存预算、哈希扩容或 checkpoint 都需要重新验证内存与恢复。

这些是可研究的候选原因，不是已经完成 profile 的结论。首先测量，
优先最小且容易证伪的优化；不要一轮同时改日志、内存布局和向量算法。
