## 2. 评审复现步骤

```bash
cd minikb
export PATH="$PWD/../.tools/node/bin:$PATH"        # 若系统已装 Node >= 20 可跳过
export SEEKDB_BINDINGS_CACHE_DIR="$PWD/.bindings"  # 原生库缓存（默认 ~/.seekdb）

npm install --legacy-peer-deps --registry=https://registry.npmmirror.com
./run.sh
```

浏览器打开 **http://127.0.0.1:8787**，等右上角徽章变成「后端：WASM/int8」或「后端：WebGPU/fp16」：

1. 点「载入示例」→ 6 条中文文档入库（可看到逐条向量化进度）。
2. 搜索「seekdb 的混合检索怎么排序？」，切换 混合 / 语义 / 关键词 三种模式，比较排序与分数。
3. 展开左下「性能面板」→ 点「测量」，得到本机当前后端的实测 JSON。
4. 换知识库：点「＋」新建集合，再导入，验证检索只落在当前集合。

**首次启动的两笔下载**（之后走缓存）：
- seekdb 原生库 ~46 MB（来自 `oceanbase-seekdb-builds.s3.ap-southeast-1.amazonaws.com`）；
- embedding 模型 ~24 MB（int8，经 `/api/hf/*` 代理从 hf-mirror 拉取）。

弱网/离线演示：应用启动后先跑 `scripts/prefetch_model.sh` 把模型缓存到 `data/hf_cache`。

## 4. 已验证 / 未验证（评审请留意）

**已验证**

- 完整链路：导入文本 → 浏览器本地生成 512 维向量 → 写入 seekdb → 查询 → 排序结果 + 原文高亮（`docs/e2e-result.json`，0 页面错误）。
- 写入持久化：重启服务后数据仍在（`data/seekdb`），`/api/docs/:id` 可把库里存的向量取回（dim=512，norm=1）。
- 三种检索都由 seekdb 执行；混合检索的 RRF 融合在**一条 SQL** 内完成，客户端不拼合。
- 后端降级：无头环境不支持 WebGPU/fp16 时自动落 `WASM/int8`，徽章提示正确，流程不受影响。
- 量化对比与 5 轮性能数据：见 `docs/技术说明.md` 与 `docs/bench.json`。

**未验证 / 已知偏差**

1. **WebGPU 正向路径没有实测数字**：本次只有无头 Chromium（无 `shader-f16`），只验证了降级。带 GPU 的 Chrome/Edge 应显示「后端：WebGPU/fp16」，届时可用性能面板补测。
2. **HNSW 近似检索在本机嵌入式构建不生效**：`APPROXIMATE` 查询恒为空，`refresh_index()` 超时（pyseekdb 同样表现），因此语义/混合走精确扫描；DDL 保留索引，修复后改回 `approximate: true` 即可。详见技术说明 §3。
3. 因此「索引刷新后新增可检索」在本实现中表现为**写入即可检索**（精确扫描无索引延迟），`/api/refresh` 保留但不阻塞主流程。
